## Purpose

Cross-platform Python CLI to manage the **Master** DJ music library on NAS (buckles) and sync to Serato and Rekordbox.

- **Source of truth:** `Master/` on NAS — all unique DJ tracks
- **This repo:** scripts, config, docs (not the music files)
- **Runtime state on NAS:** `Master/_meta/` — hash library, dedup reports (regenerated by tools)

## Windows setup

### 1. Clone

```powershell
git clone git@github.com:pbuckles22/dj-library-tools.git
cd dj-library-tools
pip install -r requirements.txt
```

### 2. Local config

Copy `config.json` → `config.local.json` (gitignored). Edit **windows** paths:

```json
{
  "master": {
    "windows": "Z:\\My.Documents\\My Music\\Master"
  },
  "serato_latest_import": {
    "windows": "~\\Music\\_Serato_\\Imported\\Latest Import"
  },
  "rekordbox_music": {
    "windows": "~\\Music\\RekordboxMusic"
  }
}
```

- Map NAS share `buckles` to a drive letter (e.g. `Z:`) or use UNC `\\buckles\My.Documents\My Music\Master`
- `config.local.json` overrides `config.json` — do not commit machine-specific paths

### 3. Verify NAS is reachable

```powershell
python dj.py dedup --days 1
```

Should load Master and report incremental/no-op — not “Master not found”.

## Commands (Windows)

Run from repo root with PowerShell or CMD:

```powershell
# Daily workflow (after copying new music into Master)
python dj.py pipeline

python dj.py pipeline --full          # full library scan
python dj.py pipeline --days 7        # last 7 days
python dj.py pipeline --no-rekordbox  # Serato only
python dj.py pipeline --no-serato     # Rekordbox only

# Individual steps
python dj.py organize
python dj.py rename
python dj.py dedup
python dj.py dedup --full

# Sync only
python dj.py sync serato
python dj.py sync rekordbox
python dj.py sync all

# Compare old folders to Master (tag-based default)
python dj.py compare "Z:\My.Documents\My Music\iTunes" "Z:\My.Documents\My Music\A"
```

Outputs: `tag_compare_in_master.txt`, `tag_compare_not_in_master.txt`, `tag_compare_delete.sh` in repo root (gitignored).

Sync uses **robocopy** on Windows (built-in).

## Recommended next steps (Windows)

### A. Re-run compare (optional but safe)

If Mac compare reports are not on this machine, re-run:

```powershell
python dj.py compare "Z:\My.Documents\My Music\A" "Z:\My.Documents\My Music\B" ...
```

Add all old subdirs (see [notes/DEDUP_OLD_LIBRARY.md](notes/DEDUP_OLD_LIBRARY.md)). Read-only.

### B. Delete confirmed dupes

After reviewing `tag_compare_not_in_master.txt`:

```powershell
# Generated script — review first; uses rm via bash if present, or delete manually on Windows
# On Windows, prefer deleting via Python or PowerShell from tag_compare_in_master.txt list
python dj.py compare ...   # regenerates tag_compare_delete.sh (bash rm commands)
```

**Note:** `tag_compare_delete.sh` is bash/`rm` — on Windows either use Git Bash/WSL to run it, or implement a small PowerShell delete from the report. Agent can help convert if needed.

### C. NewMusic → Master

```powershell
robocopy "Z:\My.Documents\My Music\NewMusic" "Z:\My.Documents\My Music\Master" /E /XD _meta
python dj.py pipeline --days 90
```

Use `--full` if NewMusic files have old modification dates.

### D. Re-sync DJ apps

```powershell
python dj.py sync all
```

Restart Serato and Rekordbox afterward.

## Pre-commit review (SDD — no PRs)

**Pull requests are not raised** in this repo. The agent pod is the pre-commit review gate — team consensus before commit.

Before every non-trivial commit, run in order (record PASS/WARN/FAIL):

1. **tester** — merge-ready command green
2. **code-reviewer** — correctness, conventions, tests for new behavior
3. **code-quality-gate** — diff-scoped maintainability
4. **tech-debt-evaluator** — note new debt; update TECH_DEBT.md if persistent
5. **security-reviewer** — when paths, subprocess, deletes, or secrets touched

Any **FAIL** blocks commit. See [.cursor/rules/pre-commit-gate.mdc](.cursor/rules/pre-commit-gate.mdc).
